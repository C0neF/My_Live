## OpenGL 内存优化（2026-11-13）

保留 OpenGL 和版本 3.0.0。JVM 以 32 MB 起步、最大堆 512 MB；播放器按需创建，播放前保存的音量、静音、硬解和缩放在创建时应用。图形缓存预算 64 MB、图片内存缓存 32 MB；mpv 前向缓存上限 32 MB，预读 4 秒，不保留已播放数据回看缓存。

- 9 项播放逻辑/延迟初始化检查和 1 项原生 GPU 检查通过。进入播放前设置不会初始化原生播放器；加载时隐藏窗口先保存暂停意图，恢复窗口按原规则继续。首次播放音量和静音正确，OpenGL 表面正常显示 H.264，硬解仍为 d3d11va-copy。
- 使用真实 MyLive、同一 JBR 21.0.12.1 和两种本地 H.264 素材，每个版本/场景各两次、连续采样 12 秒。平均工作集：首页 367 → 289 MiB，1080p60 502 → 436 MiB，1440p120 544 → 484 MiB；CPU 没有明确变化，显存基本持平。
- 启动时两版各次视频均累计 1 帧播放丢帧，正式采样区间计数未增加，解码丢帧为 0。一次诊断性 GC 未降低工作集；生产代码没有添加定时强制 GC 或工作集裁剪。

## 首页鼠标箭头卡顿的渲染兼容处理（2026-11-12）

用户确认卡顿发生在首页，鼠标箭头本身也不连贯。当前环境为 NVIDIA RTX 5060、144 Hz 显示器；应用没有显式指定渲染后端，Skiko 0.9.37.4 在 Windows 默认使用 Direct3D。这个现象与上游 [G-SYNC 导致鼠标卡顿](https://github.com/JetBrains/compose-multiplatform/issues/1648) 和 [Skiko 窗口内鼠标移动不连贯](https://github.com/JetBrains/skiko/issues/558) 的报告吻合。

- 应用启动时默认选择 OpenGL，保留显式 Skiko 环境变量和 JVM 参数的优先级，版本保持 3.0.0。
- 播放器保留 MediaMP OpenGL 后端需要的 `d3d11va-copy,auto-safe`，初始设置和用户偏好应用时使用同一个解码配置。
- 一项定向原生检查通过：始终不可见、不可聚焦的 Compose 窗口使用 RTX 5060 OpenGL，H.264 测试视频正常绘制到 Compose 表面，实际硬解为 `d3d11va-copy`。[记录](build/reports/native-rendering/hidden-opengl-video.json) 与 [应用生成的测试画面](build/reports/native-rendering/hidden-opengl-video.png) 保存于构建报告目录。
- [新单文件](build/compose/binaries/main/single-file/3.0.0/mouse-smooth/MyLive-SingleFile-3.0.0.exe) 为 319523933 字节；[后台自检收据](build/reports/single-file/mouse-smooth-3.0.0/verification.json) 确认版本 3.0.0、默认配置为 OpenGL、包内主程序与已测试构建一致。隔离缓存且外部 Java/.NET 不可用时，资料、凭据、签名、本地同步、H.264 和 WebKit 检查通过。

本次验证证明 OpenGL 与现有播放器可以正常配合；没有测量用户前台的鼠标流畅度、G-SYNC 开启状态或真实呈现帧率。需要在新版首页实际使用后确认症状是否消失。OpenGL 视频路径增加帧回读和上传；下方既有 1440p/120 fps、4K/60 fps 的 Direct3D 播放记录不代表这条新路径的性能。
